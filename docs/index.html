Descripción

Qué es el proyecto y qué resuelve.

ReservaYa es una plataforma de reservas de buses para rutas intermunicipales en Colombia. Los usuarios se registran, consultan rutas disponibles, eligen asiento según la fecha del viaje y confirman su reserva. Al reservar reciben una factura por correo electrónico con los detalles del viaje y el pago.


Cuenta con un panel de administrador para gestionar rutas (crear, editar precio y capacidad, eliminar), ver todas las reservas y monitorear el estado de la infraestructura (MySQL, Redis, RabbitMQ) en tiempo real.

Lo que se hizo

Funcionalidades implementadas.

🔐

Autenticación

Registro y login con sesiones por token guardadas en Redis. Roles de usuario y administrador.

🪑

Asientos por fecha

La disponibilidad de cada asiento depende del día. El mismo asiento se reserva en fechas distintas.

📧

Factura por correo

Al reservar, el worker envía un email con los detalles del viaje y el total pagado vía SMTP.

🗺️

Mapa de ruta

Visualización de origen y destino en mapa interactivo con Leaflet + OpenStreetMap.

🧾

Factura PDF

Generación de comprobante PDF en el navegador al confirmar la reserva.

⚙️

Panel admin

Gestión de rutas con precio configurable, reservas y métricas de ocupación.

📨

Eventos asíncronos

Cada acción publica un evento en RabbitMQ que un worker procesa y registra.

🔍

Búsqueda de rutas

Filtro en tiempo real por ciudad de origen o destino. Diseño responsive.

📊

Observabilidad

Logs JSON, Dozzle para logs en vivo y Portainer para administrar contenedores.

Despliegue en otra máquina

Guía paso a paso. Solo necesitas Git y Docker.

1

Requisitos

Instala Git y Docker Desktop. En Windows, usa WSL (wsl --install). Verifica:

git --version
docker --version
docker compose version
2

Clonar el repositorio

git clone https://github.com/nicolasgarciae/proyecto1corte.git
cd proyecto1corte
3

Crear configuración

Genera el archivo .env y edita las contraseñas:

make setup
nano .env
4

Levantar el sistema

Construye y arranca todos los contenedores:

make up

O desde imagen publicada en DockerHub:

make DOCKER_USERNAME=nicolasgarciae1 IMAGE_TAG=v1 deploy
5

Verificar

make status
curl http://localhost:8014/health

Respuesta esperada: {"status": "ok"}

6

Abrir la app

Navega a http://localhost:8014. Admin por defecto: usuario admin, contraseña admin.

Correos opcionales. Para enviar facturas por email, configura las variables SMTP_* en el .env con una cuenta de Gmail y su contraseña de aplicación. Si se dejan vacías, el sistema funciona igual pero no envía correos. La guía completa está en el README.md del repositorio.
